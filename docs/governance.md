# 肿瘤循证基准治理规则

本文件说明仓库如何落地"循证基准共建—冻结验证—撤回追溯"的治理要求。结构契约见 `contracts/`，
脱敏演示样例见 `fixtures/`，规则的可执行断言见 `test/governance.test.js`。

## 1. 决策点版本只增不改

- 每个临床决策点（`CDP-*`）维护 `versions` 序列，版本号必须连续递增（v1、v2…），
  `current_version` 始终指向最大版本。
- 指南更新导致答案变化时，**新增版本**，旧版本标记为"被取代"，但旧答案、旧证据引用、
  适用人群与当时评审记录原样保留。因此同一病例在不同证据期"两个都曾合理"的答案可以并存，
  例如 `CDP-ESO-001`：v1（2023版指南，含铂双药化疗）与 v2（2026版指南，免疫联合化疗）。
- 每个版本必须记录 `change_reason`，说明本版本产生或变更的理由。

## 2. 证据、病例与适用人群关联

- 每个版本必须关联：
  - 脱敏病例片段（`case_refs`），须在 `case_consents` 登记；
  - 指南条款或专家共识（`evidence_refs`），须在 `evidence_catalog` 登记；
  - `applicable_population`：病种、分期、生物标志物等适用人群限定。
- 证据条目带 `effective_from` / `effective_until` 与状态（有效/已撤回/已过期）。
  撤回只改状态与撤回日期，**条目不删除**。

## 3. 少数意见与专家盲审

- 未被采纳的评审意见写入 `minority_opinions`，记录主张、持意见人编号与理由，随版本永久保留。
- 每个版本必须为盲审（`blind: true`），评审人以编号出现，全员完成利益冲突申报；
  存在利益冲突的评审人记录为"回避"，不参与结论。

## 4. 病例授权与再识别风险

- `case_consents` 逐病例登记脱敏方式、是否稀有特征组合、再识别风险等级与授权使用范围。
- 高风险病例（如 `CASE-REC-0188`，稀有组合、风险高）授权范围不含"教学展示"。
- 决策点引用病例时，用途必须落在该病例的授权范围内；贡献者保留撤回权（`revocable`）。

## 5. 验证冻结与失败重跑

- 一次运行（`RUN-*`）冻结完整题集（决策点×版本的精确组合）、评分规则版本与冻结日期。
- 失败后的重跑通过 `rerun_of` 指向原运行，且必须复用**完全相同**的冻结题集、
  评分规则版本与冻结日期——只允许修复模型，不允许挑换病例。校验逻辑见 `checkRerunIntegrity`。
- 逐题结果必须给出 `explanation`，向医生呈现能力边界与证据缺口，而不仅是对错。

## 6. 指南撤回与结果作废

- 证据被撤回后，通过 `impactByEvidence` 反查所有引用该证据的决策点版本，
  再定位包含这些题目的全部运行（服务端点 `/impact?evidence=...`）。
- 不再可信的运行状态置为"已作废"，在 `invalidation` 中记录触发证据、受影响题目与原因；
  运行本身保留备查，不删除。

## 7. 全链路追溯

- 从任一结论可经 `/trace?run=...&decision=...`（或 `traceResult`）还原：
  当时的冻结日期、评分规则版本、决策点版本与答案、少数意见、变更理由、
  病例授权、证据条目及其状态、盲审评签记录与逐题评分说明。
- 研究管理者据此可从结论回溯到当时有效的病例、规则、审签人与变更理由。

> 仓库中所有病例、证据编号、模型名称与结果均为虚构演示数据。
