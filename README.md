# 肿瘤循证基准治理

本项目服务于保存消化道肿瘤临床决策、循证依据与验证记录。仓库保存领域资料、交换契约和可运行的服务入口，便于参与方在同一语义下协作。

## 领域事实

- 消化道肿瘤病种复杂且诊疗路径长，通用医学题库无法反映真实决策
- 指南更新后同一病例可能先后存在两个都曾合理的答案，历史版本必须保留
- 使用场景包括预问诊、门诊病历、影像梳理、MDT会诊和随访

## 领域模型

- **临床决策点**（`contracts/decision-point.schema.json`）：按场景与适用人群定义，关联指南条款、专家共识与脱敏病例片段；修订只新增版本，争议结论的少数意见随版本保留，每次修订记录变更理由与审签人。
- **循证依据**（`contracts/evidence.schema.json`）：指南条款、专家共识、病例片段统一登记，带生效与失效日期；撤回只标记状态，从不删除。
- **病例治理**（`contracts/case-governance.schema.json`）：病例贡献者的授权范围、稀有组合的再识别风险评估与缓释、盲审专家的利益冲突回避。
- **基准冻结与验证**（`contracts/benchmark.schema.json`）：一次验证冻结完整题集与评分规则；失败重跑引用同一冻结集，不得挑换病例；运行结果记录能力边界与证据缺口。

## 治理红线（由测试强制）

`npm test` 会校验：

1. 版本号严格递增，每次修订必有变更理由、审签人与循证依据
2. 所有证据引用可解析，现行版本不得引用已撤回依据
3. 指南撤回后可定位受影响的版本、冻结题集与验证运行
4. 失败重跑引用同一冻结题集
5. 病例片段仅在授权范围内使用，已撤销授权不得进入冻结题集
6. 稀有组合病例必须完成再识别风险评估并给出缓释措施
7. 申报利益冲突的专家不得出现在相关版本的审签人中
8. 任一验证结论可追溯到当时有效的病例、评分规则、审签人与变更理由

## 目录说明

- `contracts/` 保存交换数据的结构约定。
- `fixtures/` 提供去标识的领域样例（决策点、依据、病例治理、基准冻结与运行）。
- `src/catalog.js` 提供资料载入、撤回影响定位（`findEvidenceImpact`）与结论追溯（`traceConclusion`）。
- `src/server.js` 提供服务入口。
- `test/` 核对领域资料与治理红线。

## 服务入口

- `GET /health` 健康检查
- `GET /context` 领域上下文
- `GET /catalog` 全量领域资料
- `GET /impact?evidence=<依据ID>` 撤回/失效影响定位
- `GET /trace?run=<运行ID>&decision_point=<决策点ID>` 结论追溯链

## 本地检查

运行 `npm test` 可以检查当前资料与服务入口。
